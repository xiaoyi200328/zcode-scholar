# Playbook: design（实验设计）

一句话职责：把假说变成**可执行、可辩护的实验方案**——湿实验优先覆盖（本仓库最大空白），干实验衔接 Analysis Loop。

## Pre-flight

1. **假说就绪门**：还没有明确研究问题/假说时，Read `.claude/skills/research-ideation/SKILL.md` 做 5W1H 构思；有多个候选方向时给出 2-3 个方案让用户选（不暗选）
2. **输入盘点**：收集——研究对象（细胞系/动物/人群/数据集）、可用平台与预算量级、时间约束、已有数据。缺项列进方案的 Open Questions，不阻塞设计

## Stage A: 假说可证伪化

把模糊想法改写为可证伪格式，否则后续设计无从谈起：

> 在 **[条件/模型]** 中，**[干预/暴露 X]** 通过 **[机制 Y（可选）]** 影响 **[读出 Z]**；
> 若 X 改变而 Z 未按预期改变，则假说被否定。

自查：能否设计一个"假说为真则结果必须相反"的实验？说不出 → 假说不合格，回炉。

## Stage B: 设计六要素（湿实验主干）

1. **变量定义**：自变量（处理/分组，含梯度：剂量×时间矩阵）、因变量（读出指标，注明检测方法）、混杂变量（周龄/性别/代次/接种密度/批次…逐一列控制手段）
2. **对照体系**（每组实验必答"对照是什么"）：

   | 对照类型 | 用途 | 典型例子 |
   |---------|------|---------|
   | 阴性/溶媒对照 | 基线 | vehicle、siNC、空载 vector |
   | 阳性对照 | 体系有效性 | 已知响应物、标准药物 |
   | 同型/无抗体对照 | 特异性 | flow 同型 IgG、WB 无一抗 |
   | 参照对照 | 归一化 | loading control（β-actin）、内参基因（GAPDH，需验证稳定） |

3. **随机化与盲法**：分组随机化（动物按体重分层随机）；结果测量盲法（尤其动物表型与病理评分）；遵循 ARRIVE 指南条目
4. **重复设计**：**生物学重复**（独立个体/独立培养，统计的 n）起步 n≥3，动物实验按 power analysis 定；**技术重复**（同一样本复测，只降操作误差）**不得计入 n**——这是 reviewer 第一枪
5. **样本量依据**：有先验效应量 → power analysis（α=0.05，power=0.80）；无先验 → pilot 估计或引用同类文献依据，方案中写明计算过程
6. **批次控制**：关键比较同批完成；无法同批 → 桥接样本或随机化铺板，批次作为因子记录进数据表

## Stage C: 湿实验专项清单

- [ ] 关键试剂可溯：抗体（货号/验证类型/物种反应性/有引用）、细胞系（STR 鉴定 + 支原体阴性）、动物（背景株/周龄/性别匹配）
- [ ] 关键结论有正交验证策略：至少两条独立手段（如敲减 + 过表达双向、药理抑制 + 遗传操作、rescue 实验证明特异性）
- [ ] 体系未建立时先 pilot：定剂量/时间窗/转染效率门槛，pilot 结果写进方案再开正式实验
- [ ] 样本采集与保存计划：取材时间点、冻存条件、避免反复冻融、分装规则
- [ ] 记录与数据管理：孔板图、原始文件命名规则、实验记录同步（可用 `.claude/skills/obsidian-experiment-log/`）

## Stage D: 干实验分支

1. **数据需求清单**：需要什么变量/多少样本/什么格式；自有数据不够 → public 数据库（TCGA/GEO/CPAT 等）补充，注明 accession
2. **cohort 定义**：纳入/排除标准写成文，分析前冻结
3. **分析计划预注册**：先写 SAP（主要终点、统计方法、多重校正策略）再看数据——防 p-hacking
4. **大型分析桥接**：多模块组学分析 → Read `.claude/skills/sp-planning/SKILL.md` 生成 module-centric PLAN → 按 `/research analyze` 的 Analysis Loop 路径执行

## Stage E: 缺陷自查（reviewer 视角，定稿前过一遍）

| 常见 reject 理由 | 本方案防线 |
|-----------------|-----------|
| 无生物学重复 / 技术重复当 n | 六要素第 4 条 |
| 关键结论只有单一手段 | Stage C 正交验证 |
| 无随机化/盲法（动物） | 六要素第 3 条 + ARRIVE |
| 样本量拍脑袋 | 六要素第 5 条写明依据 |
| 批次与处理混杂 | 六要素第 6 条 |
| 无阳性对照，体系存疑 | 对照体系表 |
| 读出指标与假说错位 | Stage A 回炉核对 |

## Output Contract

- 产出 `Experiments/experiment-design-{slug}.md`，结构：背景与假说 → 设计总表（分组×处理×读出×重复）→ 对照表 → 样本量依据 → 时间线 → 风险与预案 → Open Questions
- 方案经用户确认后（不确认不开工）， wet 实验进入执行记录（obsidian-experiment-log），干实验进入 analyze 模式
- **Next Steps**：实验跑完拿到数据 → `/research analyze`；设计阶段发现方法不熟 → `/research survey`

## 常见错误

| 错误 | 后果 | 防线 |
|------|------|------|
| 假说不可证伪就开工 | 全套实验白做 | Stage A 自查 |
| 无 pilot 直接正式实验 | 剂量/时间窗错误，整批报废 | Stage C pilot 决策 |
| 干实验不写 SAP 先看数据 | p-hacking 嫌疑，结果不可信 | Stage D 预注册 |
| 方案只有用户口述、未落盘 | 执行漂移，事后无法辩护 | Output Contract 强制落盘 |
